## 编码约定
- 所有代码用 Java 21，充分利用 Virtual Thread
- 模块间通过接口解耦，新增 Channel/Tool 只加新模块不改 core
- 敏感配置（API key）走环境变量 ${VAR_NAME}，不明文写 YAML
- 日志用 Logback 结构化 JSON（MDC session_id + kv 字段）；**日志参数不带用户可控值**
  （sessionId/工具名等——FindSecBugs CRLF_INJECTION_LOGS 门禁会拦，关联信息在审计表）
- 遵循 CLAUDE.md 与 .specify/memory/constitution.md 的 9 条宪法原则
- 设计文档写作规则（/axion-design）：课件只读不回写（docs/requirements/ 即未来课件）；冲突必须
  停下请用户拍板并附两方案优缺点；每份设计文档必配对齐方案描述的流程图（浅/深双版本）
- 构建：先按"实施环境"export 后再 `mvn clean package`；SQLite 测试库用 `:memory:` + pool=1
- 实施顺序以 tasks.md 的 [P] 并行标记与阶段依赖为准，每个用户故事完成后跑其 Independent Test
- 编译门禁含 Error Prone `-Werror`：`LocalDateTime.now()` 要显式时区、`split(regex)` 要 `-1` 参数、
  `toLowerCase()` 要 `Locale.ROOT`、字节转 String 要显式 UTF_8
- 手工建表（schema.sql）是唯一真相源（ddl-auto: none）——新表 DDL 增量追加，测试执行同一份脚本；
  建表脚本由 boot 启动接线（spring.sql.init.mode=always + classpath:schema.sql，SQLite 不被视为
  embedded 必须显式 always）
- 人工验收用「临时 harness」模式（真装配 + 真落库 + 真模型，@Tag("integration")），不进交付物、
  验收后删除；方法见 `.claude/skills/axion-spec/references/manual-acceptance.md`
- CLI 实跑经验：终端输入编码跟随 `console().charset()`（硬编码 UTF-8 会把 GBK 终端读乱）；
  打包唯一入口 = axion-boot（mainClass=AxionCli，cli 模块 repackage skip 防嵌套 fat jar）；
  重命令 `web(NONE)` 不起 Tomcat；Windows 下 jar 被瞬时锁时等待数秒重试打包
